# 방안 1 — NLP 자연어 처리

## 목적

5개국 언어로 섞인 원문을 두 가지로 변환한다.

1. **언어와 무관하게 비교 가능한 벡터** — 이슈 클러스터링과 매칭의 기반
2. **한국어 텍스트** — 사용자가 읽는 제목과 요약

세 단계로 나뉘며, 각 단계는 독립된 모델이 담당한다.
**세 모델 모두 자체 학습 없이 사전학습 가중치를 그대로 사용**하고,
학습 대신 입력 규약과 후처리 설계로 품질을 확보한다.

---

## 1단계 — 헤드라인 · 원문 임베딩

**모델** multilingual-e5-base (278M 파라미터 · 출력 768차원)
**학습** 없음
**입력** 원문 언어 텍스트 (번역 전)

### 입력 규약

E5 계열은 프리픽스 규약을 가진다. 문서 인코딩과 질의 인코딩에 서로 다른 접두어를
붙여야 사전학습 시 분포와 일치한다. 기사 헤드라인과 본문은 모두 문서 측 접두어를 쓴다.

### 필수 후처리 — 평균 중심화

다국어 문장 임베딩 모델은 **anisotropy** 문제를 갖는다. 모든 벡터가 공간의 좁은
원뿔 안에 몰려 있어, 의미가 전혀 무관한 문장 쌍도 코사인 유사도가 0.7~0.8로 나온다.
이 상태에서는 임계값을 어디에 두어도 클러스터가 분리되지 않는다.

> **사전 검증에서 확인된 문제**
> 임계값 0.82를 적용했을 때 서로 무관한 기사 3,766건이 하나의 거대 클러스터로 병합되었다.

배치 단위로 임베딩의 평균 벡터를 구해 전체에서 빼면, 모든 문장이 공통으로 향하는
방향(의미와 무관한 편향 성분)이 제거되고 그 아래 가라앉아 있던 실제 의미 차이가 드러난다.

| 구분 | 중심화 전 | 중심화 후 |
|------|-----------|-----------|
| 무관 기사 쌍 (p99) | 약 0.80 | **0.24** |
| 유관 기사 쌍 (중앙값) | 약 0.85 | **0.48** |

두 분포가 분리되어 임계값 기반 클러스터링이 동작하는 상태가 되었다.

### 출력 재사용

이 벡터는 세 곳에서 재사용된다. 기사당 임베딩 연산은 1회뿐이다.

1. 이슈 클러스터링 · 이슈 매칭
2. 카테고리 분류기 입력 (방안 2)
3. 향후 신뢰도 스코어링의 헤드라인-본문 일관성 지표

---

## 2단계 — 헤드라인 번역

**모델** NLLB-200-3.3B
**학습** 없음
**입력** 원문 헤드라인 (10~20 토큰)

NLLB-200은 200개 언어를 지원하며, **영어를 경유하지 않고 원문 언어에서 한국어로
직접 번역**한다. 중간 언어를 거치지 않으므로 의미 손실이 적다.

헤드라인은 짧아 생성 비용이 낮다. 따라서 **수집 직후 실시간으로 처리**하여,
본문 처리가 끝나기 전에도 한국어 제목으로 목록에 노출할 수 있다.

---

## 3단계 — 본문 요약 및 번역

본문 전체를 번역하면 비용이 감당되지 않는다. **처리 순서를 뒤집는다.**

```
원문 (수천 토큰) ──요약──▶ 원문 언어 3~4문장 ──번역──▶ 한국어 요약
```

| 언어 | 요약 모델 | 학습 |
|------|-----------|------|
| 한국어 | KoBART | 없음 |
| 영어 | BART-large-CNN | 없음 |
| 그 외 | mT5-XLSum | 없음 |

번역은 1단계와 동일하게 NLLB-200-3.3B를 사용한다.

### 선택 근거

**생성 비용 감소** — 번역 모델의 비용은 출력 길이에 비례한다.
번역 대상이 본문 전체에서 3~4문장으로 줄면 비용이 약 1/10 수준이 된다.

**품질 보존** — 번역을 먼저 하면 번역 오차가 요약 입력에 누적된다.
원문 언어 그대로 요약해야 언어별 특화 요약 모델의 성능을 온전히 쓸 수 있다.

---

## 출력

방안 1은 **라벨을 출력하지 않는다.** 벡터와 텍스트를 출력한다.

| 필드 | 타입 | 설명 |
|------|------|------|
| `embedding_headline` | float[768] | 헤드라인 임베딩 (평균 중심화 적용) |
| `embedding_body` | float[768] | 본문 임베딩 (평균 중심화 적용) |
| `headline_ko` | string | 한국어 헤드라인 |
| `summary_ko` | string | 한국어 요약 (3~4문장) |
| `summary_original` | string | 원문 언어 요약 (번역 전 원본) |

# 방안 2 — 국가별 논조 분석

## 목적

같은 이슈를 각국 언론이 어떤 논조로 다루는지 비교한다.
세 방안 중 **유일하게 자체 학습이 필요한 부분**이다.

## 핵심 과제 — 분야별 극성 반전

같은 표현이라도 분야에 따라 긍정과 부정이 뒤집힌다.

| 표현 | 스포츠 | 경제 |
|------|--------|------|
| 완파 | 긍정 (압승) | 부정 (시설 파괴) |
| 과열 | 중립 (경기 열기) | 부정 (버블) |
| 공세 | 중립 (공격 전개) | 부정 (무역 마찰) |

단일 범용 감정 분류기로는 이 반전을 잡을 수 없다.
따라서 6개 분야(**정치 · 경제 · 사회 · 기술 · 문화 · 스포츠**)마다 전용 모델을 두고,
**분류 → 라우팅 → 논조 판정** 순서로 처리한다.

```
기사 ──▶ 카테고리 분류기 ──▶ 해당 분야 전용 모델 ──▶ 논조 라벨 + 점수
         (E5 임베딩 활용)      (6종 중 1개 선택)
```

---

## 모델 구성 ① 카테고리 분류기

**모델** E5 임베딩 위에 얹는 얕은 신경망 헤드 (약 20만 파라미터)
**입력** 방안 1에서 이미 계산된 768차원 벡터
**출력** 6개 분야 중 1개
**추가 추론 비용** 없음 (행렬 연산만 수행)

### 별도 언어 모델을 쓰지 않는 이유

카테고리 분류는 **주제 분류**다. E5는 애초에 주제 유사도를 학습한 모델이므로
임베딩에 이미 주제 정보가 충분히 담겨 있고, 얕은 헤드만으로 분리가 가능하다.
언어 모델을 한 번 더 통과시킬 이유가 없다.

반면 논조 분류는 **극성 판정**이라 문장 내 특정 표현에 주목해야 한다.
한 벡터로 압축된 정보만으로는 부족하므로, 그쪽은 별도 언어 모델을 쓴다.

### 언어 무관성

E5 임베딩 공간은 언어 의존도가 낮으므로, 한 언어로 학습한 헤드가 다른 언어
기사에도 동작한다. 따라서 카테고리 분류는 **번역 이전, 원문 임베딩 단계에서 수행**한다.

### 학습 데이터

별도 작업이 필요 없다. 논조 모델 6종을 학습하려면 학습 코퍼스를 분야별로 나눠야 하고,
그 과정에서 카테고리 라벨이 이미 생성되기 때문이다.

---

## 모델 구성 ② 논조 분석 모델 6종

사람 라벨링 인력이 없으므로, **기존 모델이 라벨을 만들고 그것으로 경량 모델을
학습시키는** teacher-student 증류 방식을 택한다.

```
[오프라인 1회]  Teacher (제로샷 NLI) ──분야별 가설로 라벨 대량 생성──▶ Student 6종 학습

[런타임]        Student 1개만 실행
```

### Teacher

**모델** mDeBERTa-v3-base-mnli-xnli
**역할** 학습 데이터 라벨링 전용 (서비스 런타임에서는 미사용)

자연어 추론(NLI)으로 학습된 모델이라, "이 기사는 ○○에 해당한다" 형태의 가설을 넣어
**라벨 없이** 분류할 수 있다. 정확하지만 가설 개수만큼 추론을 반복해야 해서
런타임에 두기엔 무겁다. 따라서 오프라인 라벨링에만 사용한다.

### 카테고리별 가설 설계

이 가설 템플릿이 "분야별 전용 모델"의 실체다. 분야마다 긍정·부정의 정의가 다르다.

| 카테고리 | 긍정 가설 | 부정 가설 |
|----------|-----------|-----------|
| 정치 | 해당 정치 주체의 행보를 긍정적으로 평가한다 | 해당 정치 주체의 행보를 비판적으로 다룬다 |
| 경제 | 경제 상황·전망을 낙관적으로 서술한다 | 경제 상황·전망을 비관적으로 서술한다 |
| 사회 | 사회적 개선이나 문제 해결을 다룬다 | 사회적 갈등이나 피해를 다룬다 |
| 기술 | 기술의 성과나 기대 효과를 다룬다 | 기술의 부작용이나 위험을 다룬다 |
| 문화 | 작품·인물을 호평한다 | 작품·인물을 혹평한다 |
| 스포츠 | 해당 팀·선수의 좋은 성과를 다룬다 | 해당 팀·선수의 부진이나 패배를 다룬다 |

**긍정 가설과 부정 가설은 독립적으로 채점한다.** 두 확률의 합을 1로 강제하면
"긍정과 부정이 동시에 높은" 양가적 상태를 표현할 수 없기 때문이다.
이 판단이 뒤의 혼합 라벨 설계로 이어진다.

### 학습 데이터 구축 절차

| 단계 | 내용 |
|------|------|
| 1 | 수집 코퍼스에서 학습용 기사 확보 |
| 2 | Teacher로 카테고리 라벨 생성 → 6개 분할 |
| 3 | 분할별로 해당 카테고리 가설을 적용해 논조 라벨 생성 |
| 4 | **품질 게이트** — Teacher가 확신하지 못한 애매한 샘플 제외 |
| 5 | 분야별 학습셋 확정. 데이터가 부족한 분야는 오버샘플링 |

4단계 품질 게이트가 중요하다. Teacher가 확신하지 못한 샘플까지 학습하면
Student가 그 불확실성을 노이즈로 흡수한다. 걸러내면 학습셋은 줄지만 정확도는 오른다.

- **사람 라벨링 0건** — 전량 Teacher가 생성
- **오프라인 1회** — 서비스 운영 중 재학습하지 않음

### Student

**후보 모델** KLUE-RoBERTa-base (한국어) 또는 Multilingual-MiniLM (다국어) · 110~120M
**개수** 6종 (카테고리당 1개)
**입력** 한국어 헤드라인 + 요약 (방안 1의 산출물)
**출력** 긍정 확률, 부정 확률 (독립 산출)

**증류 방식** Teacher가 산출한 확률값을 그대로 학습 목표로 사용한다.
0 또는 1의 이분 라벨로 변환하면 Teacher가 가진 확신도 정보가 버려진다.

**추론 비용** Teacher는 가설 개수만큼 반복 추론이 필요했지만, Student는
**기사당 1회**로 끝난다. 카테고리 분류기는 추가 추론이 없으므로,
논조 분석 전체의 언어 모델 추론은 **기사당 총 1회**다.

**입력 언어** 방안 1에서 한국어 요약을 이미 만들므로 추가 비용이 없고,
단일 언어만 다루면 한국어 특화 모델을 쓸 수 있어 같은 크기의 다국어 모델보다
성능이 높다. "완파" 같은 극성 반전 사례 자체가 한국어 어휘 문제라는 점에서도 일관된다.
다만 번역 과정에서 극성 뉘앙스가 약해질 수 있으므로, 원문 기반 판정과 샘플 비교하여
손실이 크면 다국어 Student로 전환한다.

**초기 후보값** (실험으로 확정)

| 항목 | 초기값 |
|------|--------|
| 학습 데이터 규모 | 분야별 3,000~5,000건 (총 약 24,000건) |
| 학습 반복 | 3~5 epoch |
| 입력 최대 길이 | 256 토큰 |

## 라벨 체계

Student가 산출한 두 확률로부터 라벨을 결정한다.

| 라벨 | 판정 조건 | 의미 |
|------|-----------|------|
| `mixed` | 두 확률 중 **작은 쪽**이 임계값 이상 | 긍정·부정이 동시에 존재 |
| `neutral` | 두 확률 중 **큰 쪽**이 임계값 미만 | 뚜렷한 극성 없음 |
| `positive` | 위에 해당하지 않고 긍정 확률이 더 큼 | 긍정 논조 |
| `negative` | 위에 해당하지 않고 부정 확률이 더 큼 | 부정 논조 |

**혼합 라벨이 필요한 이유** 실제 기사에는 양가적 서술이 빈번하다.
"수출은 늘었지만 내수는 얼어붙었다" 같은 문장은 긍정과 부정이 함께 존재하며,
단일 확률 분포로는 이를 중립으로 뭉갤 수밖에 없다. 두 확률을 독립으로 두고
**작은 쪽이 임계값을 넘는지** 확인하면 이 상태를 구분할 수 있다.

**논조 점수 (0~100)** 라벨과 별개로 연속 점수를 함께 제공한다.
대시보드에서 정렬과 그라데이션 표현이 필요하기 때문이다.
긍정 확률에서 부정 확률을 뺀 값을 0~100 구간으로 선형 변환한다.

| 긍정 확률 | 부정 확률 | 점수 | 라벨 |
|-----------|-----------|------|------|
| 0.90 | 0.05 | 92.5 | positive |
| 0.71 | 0.68 | 51.5 | **mixed** |
| 0.12 | 0.09 | 51.5 | **neutral** |
| 0.10 | 0.85 | 12.5 | negative |

> **주의** 혼합과 중립은 **점수가 같게 나올 수 있다.**
> 점수만 저장하면 두 상태가 구분되지 않으므로, 라벨과 점수를 반드시 함께 저장하고
> UI에서는 라벨로 구분한다.

## 출력

| 필드 | 타입 | 설명 |
|------|------|------|
| `category` | enum | 정치 / 경제 / 사회 / 기술 / 문화 / 스포츠 |
| `category_confidence` | float | 카테고리 분류 확신도 (0~1) |
| `p_positive` | float | 긍정 확률 (0~1) |
| `p_negative` | float | 부정 확률 (0~1) |
| `tone_label` | enum | positive / negative / neutral / mixed |
| `tone_score` | float | 논조 점수 (0~100) |
| `tone_confidence` | float | 논조 판정 확신도 (0~1) |
| `model_version` | string | 사용된 Student 모델 버전 |

**집계 범위** AI는 **기사 단위 결과까지만** 생성한다.
이슈 × 국가 단위 논조 비율 집계는 백엔드 담당이다.

# 방안 3 — 신규 이슈 도출

## 목적

기존 어떤 이슈에도 속하지 않는 기사 묶음을 **사람이 읽을 수 있는 이슈로 정의**한다.
지금 막 떠오르는 이슈를 지구본에 실시간 반영하는 경로다.

## 모델

**모델** GMS LLM
**학습** 없음 — 프롬프트 기반
**호출 단위** 기사가 아닌 **클러스터당 1회**

### 학습하지 않는 이유

신규 이슈는 정의상 학습 데이터가 존재하지 않는다. 과거 이슈로 모델을 학습시켜도,
새로 등장하는 사안의 명명 방식은 매번 다르다. LLM의 사전 지식과 지시 이행 능력을
그대로 쓰는 편이 적합하다. 호출이 클러스터 단위라 빈도가 낮아 비용도 감당 가능하다.

---

## 입력 구성

클러스터링 결과에서 다음을 추려 전달한다.

| 항목 | 내용 |
|------|------|
| 대표 기사 | 클러스터 중심에 가까운 상위 N건의 한국어 제목 + 요약 |
| 군집 키워드 | 빈도 상위 키워드 |
| 메타 정보 | 보도 국가 목록, 언론사 수, 최초 보도 시각 |
| 기존 이슈 후보 | 임베딩 유사도 상위 N건 (중복 판별용) |

---

## LLM에 요구할 작업

| 작업 | 요구사항 |
|------|----------|
| 이슈명 생성 | 짧은 명사구. 특정 언론사의 표현을 그대로 쓰지 않을 것 |
| 한 줄 요약 | 사실만 기술. 논평·추측 금지 |
| 키워드 추출 | 3~5개 |
| 중복 판별 | 제시된 기존 이슈 중 같은 사안이 있으면 지목, 없으면 신규 |
| 확신도 | 기사들이 하나의 사안으로 묶이는 정도를 0~1로 |

**중복 판별을 LLM에 맡기는 이유** 임베딩 유사도만으로는 "같은 사안의 후속 보도"와
"표현이 비슷한 별개 사안"을 구분하기 어렵다. 유사도 상위 후보를 함께 제시하고
LLM이 최종 판단하게 하면 이슈 목록이 중복으로 오염되는 것을 막을 수 있다.

---

## 출력

| 필드 | 타입 | 설명 |
|------|------|------|
| `issue_name` | string | 이슈명 (짧은 명사구) |
| `one_line_summary` | string | 한 줄 요약 |
| `keywords` | string[] | 키워드 3~5개 |
| `duplicate_of` | string \| null | 중복 시 기존 이슈 ID, 신규면 null |
| `confidence` | float | 이슈 묶음 확신도 (0~1) |

## 출력 검증

LLM 출력은 그대로 신뢰하지 않고, 다음 검사를 통과해야 등록된다.

| 검사 | 조건 | 실패 시 처리 |
|------|------|--------------|
| 형식 | 요구한 구조와 일치 | 재시도 후 폐기 |
| 길이 제약 | 이슈명·요약 길이 한도 내 | 재시도 |
| 확신도 | 임계값 이상 | 등록 보류, 다음 배치로 이월 |
| 중복 판정 | 신규인 경우에만 등록 | 기존 이슈에 기사만 할당 |
| 이슈명 충돌 | 기존 이슈명과 완전 일치하지 않을 것 | 재시도 |

통과한 이슈는 신규 등록되고, 해당 군집의 기사에 이슈 ID가 할당된다.
