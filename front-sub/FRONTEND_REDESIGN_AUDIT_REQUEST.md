# Frontend Redesign Audit Request

## 0. 목적

현재 프로젝트의 프론트엔드를 대대적으로 개편하기 전에, **현재 구현/백엔드/ERD/데이터 구조를 먼저 정확히 분석하고**
실제로 구현 가능한 프론트엔드 개편안을 문서로 제안해 주세요.

이번 작업에서는 **코드를 수정하지 않습니다.**
분석과 설계만 수행하고, 최종 결과를 Markdown 문서로 작성합니다.

---

## 1. 프로젝트 핵심 맥락

이 서비스는 여러 국가의 뉴스를 수집·분석하여 사용자에게 보여주는 글로벌 뉴스 서비스입니다.

핵심 데이터 구조에는 다음과 같은 계층이 있습니다.

```text
field
  ↓
theme
  ↓
issue
  ↓
article
```

ERD에서 확인 가능한 `field → theme → issue` 관계뿐 아니라,
실제 backend entity / repository / API / DB migration 또는 schema를 확인하여
전체 데이터 구조를 다시 파악해 주세요.

특히 기사에는 국가, 분야/테마/이슈, 논조, 관련도, 발행 시각 등
프론트엔드에서 활용 가능한 데이터가 더 존재할 수 있으므로
현재 프론트에서 사용 중인 데이터와 **DB/Backend에는 있지만 사용하지 않는 데이터**를 구분해 주세요.

향후 **회원가입/로그인 기능도 추가될 예정**입니다.
따라서 비회원 UX만 보는 것이 아니라,
로그인 사용자에게 제공할 수 있는 개인화 기능까지 함께 검토해 주세요.

## 2. 현재 프론트엔드에서 느끼는 문제

### 2-1. 디자인이 단조로움

현재 화면이 일반적인 카드/리스트 중심으로 보여
"전 세계 뉴스를 데이터로 탐색한다"는 서비스의 특징이 충분히 드러나지 않습니다.

단순히 색상이나 카드 디자인만 바꾸는 수준이 아니라,
정보 구조와 인터랙션 자체를 다시 검토해 주세요.

### 2-2. 지구본 활용도가 낮음

지구본은 이 서비스의 정체성을 나타낼 수 있는 핵심 UI인데
현재는 시각적 장식 또는 제한적인 이동 수단에 가까운지 확인해 주세요.

지구본이 실제 탐색의 중심이 될 수 있는지 검토해 주세요.

예:

- 국가 선택
- 해당 국가의 주요 이슈 즉시 표시
- 국가별 분야/테마 분포
- 특정 이슈가 여러 국가에서 어떻게 다뤄지는지 표시
- 논조 또는 관심도 차이 표현
- 시간 변화에 따른 이슈 확산
- 지구본 선택 결과를 별도 페이지 이동 없이 side panel / bottom sheet / overlay로 확인

위 예시를 그대로 구현하라는 뜻은 아닙니다.
현재 데이터/API로 실제 가능한 기능과 추가 개발이 필요한 기능을 구분해서 제안해 주세요.

### 2-3. 화면 Depth가 깊음

현재 일부 주요 기능이 3 depth를 넘어가는 문제가 있습니다.

사용자가 핵심 정보를 보기 위해

```text
메인
→ 페이지 A
→ 페이지 B
→ 페이지 C
→ 상세
```

처럼 이동해야 하는 부분이 있는지 전체 route/navigation을 조사해 주세요.

가능하면 핵심 기능은 **3 depth 이내**,
주요 탐색 행동은 **1~2번의 interaction** 안에 도달하도록 재설계해 주세요.

페이지를 계속 추가하는 대신 다음 방식도 적극 검토해 주세요.

- 탭
- contextual side panel
- drawer
- modal
- split view
- filter
- expandable section
- 지구본과 기사/이슈 패널의 동시 표시

현재 repository를 직접 읽어서 판단해 주세요.

특히 다음을 확인해 주세요.

```text

API controller / service / DTO

```

회원 관련 코드가 이미 일부 존재한다면 그것도 확인해 주세요.

추측으로 기능을 만들지 말고 다음 세 가지로 구분해 주세요.

```text
A. 현재 데이터/API만으로 바로 구현 가능
B. Backend API 추가 정도로 구현 가능
C. DB schema 또는 파이프라인 변경까지 필요한 기능
```

## 4. ERD/Backend 데이터를 활용한 숨은 기능 발굴

현재 화면에 없는 기능 중
**이미 DB에 저장되어 있거나 Backend에서 제공할 수 있는 데이터를 활용해 사용자 가치가 생기는 기능**을 찾아 주세요.

예를 들어 다음 관점에서 조사해 주세요.

### 뉴스 탐색

- field / theme / issue 계층을 이용한 자연스러운 탐색
- issue 중심 기사 묶음
- 국가별 같은 이슈 비교
- 최근 떠오르는 이슈
- 시간에 따른 이슈 변화
- 관련 기사 탐색
- 국가/분야/테마 조합 필터

### 데이터 기반 시각화

실제 DB 필드와 통계 데이터가 존재하는 경우에만 다음을 검토합니다.

- 국가별 기사량
- 국가별 주요 이슈
- 국가별 논조 차이
- 이슈별 국가 분포
- 분야/테마 분포
- 시간대별 관심도 변화
- issue first_seen_at 등을 활용한 발생/확산 표현

### 회원 기능 추가 이후

회원가입 기능이 추가됐을 때 다음 기능이 가능한지
현재/예정 schema와 backend를 기준으로 분석해 주세요.

- 관심 국가
- 관심 분야/테마
- 관심 이슈
- 기사 북마크
- 최근 본 기사
- 개인화 홈
- 개인화 뉴스 필터
- 저장한 이슈
- 알림 또는 추적

DB나 API가 없는 기능은 "이미 가능한 기능"처럼 표현하지 말고
필요한 Backend/DB 작업을 명확히 표시해 주세요.

## 5. UX 개편 시 중요한 기준

### 서비스 정체성

일반적인 뉴스 포털을 복제하지 말고,

> "세계에서 지금 어떤 일이 벌어지고 있고,
> 같은 이슈를 각 국가가 어떻게 바라보고 있는지 탐색하는 서비스"

라는 정체성이 화면에서 느껴지도록 제안해 주세요.

### 지구본

지구본을 장식 요소가 아니라
**글로벌 뉴스 탐색의 primary interface 중 하나**로 활용하는 방안을 검토해 주세요.

다만 모든 기능을 억지로 지구본에 넣지는 마세요.
리스트가 더 적합한 기능은 리스트를 사용해야 합니다.

### 정보 밀도

한 화면에 지나치게 많은 카드가 반복되는 디자인은 피하고,
핵심 정보에 우선순위를 두어 주세요.

### Navigation Depth

주요 기능은 3 depth 이내를 목표로 합니다.

특히 다음 사용자 행동의 click/depth를 계산해 주세요.

- 특정 국가의 주요 뉴스 보기
- 특정 이슈 상세 보기
- 특정 분야 → 테마 → 기사 탐색
- 같은 이슈의 국가별 기사 비교
- 기사 상세 열기
- 로그인 후 관심 콘텐츠 확인

## 6. 회원가입 도입을 전제로 한 IA 검토

회원가입 전과 후의 UX를 나누어 설계해 주세요.

예:

```text
비회원
- 글로벌 이슈 탐색
- 국가 탐색
- 기사/이슈 열람

회원
- 관심 국가/테마 기반 개인화
- 북마크
- 관심 이슈 추적
- 개인화 홈
```

단, 위 기능을 모두 구현하라는 뜻은 아닙니다.

현재 backend와 ERD를 확인한 뒤
실현 가능성/개발비용/사용자 가치를 기준으로 우선순위를 정해 주세요.

회원가입 기능 자체도 기존 architecture를 확인하고
필요한 화면 흐름을 제안해 주세요.

예:

```text
회원가입 / 로그인
→ 최초 관심사 설정(optional)
→ 메인
→ 마이페이지 / 개인화 영역
```

## 7. 현재 프론트 전체 진단

현재 frontend의 모든 주요 페이지와 route를 확인하고 아래를 정리해 주세요.

- 페이지 목적
- 사용 데이터/API
- 주요 컴포넌트
- 현재 navigation depth
- 다른 페이지와 중복되는 기능
- 없어도 되는 단계
- 한 화면으로 합칠 수 있는 페이지
- 지구본과 통합할 수 있는 페이지
- 모바일/반응형에서 문제가 될 가능성
- loading / empty / error 상태
- 사용자에게 의미가 불명확한 정보
- 데이터는 있는데 사용하지 않는 요소

## 8. 새로운 Information Architecture 제안

분석 후 새로운 전체 IA를 제안해 주세요.

각 페이지의 역할과 사용자가 어떻게 이동하는지 설명해야 합니다.

특히 기존보다 depth가 어떻게 줄어드는지도 비교해 주세요.

가능하면 다음과 같이 표현해 주세요.

```text
현재
Home
 └─ ...
     └─ ...
         └─ ...

개편안
Home / Globe
 ├─ Country Panel
 ├─ Issue Panel
 ├─ Article Panel
 └─ Explore
```

위 구조는 예시입니다.
실제 코드를 분석한 결과를 기준으로 더 적절한 구조를 제안해 주세요.

현재 디자인을 그대로 유지해야 한다는 제약은 없습니다.

"예쁘게 만드는 것"이 아니라 **서비스의 데이터 구조를 사용자가 이해하기 쉽게 만드는 것**입니다.

- visual hierarchy
- layout

- 색 사용 원칙
- 지구본과 데이터 panel의 관계

- interaction / transition의 역할

가능하면 일반적인 뉴스 카드 대시보드와 차별화된 방향을 제시해 주세요.

## 15. 가장 중요한 질문

최종 문서는 단순히

가 아니라 아래 질문에 답해야 합니다.

> 사용자가 전 세계 뉴스를 가장 짧고 직관적인 경로로 탐색할 수 있도록
> 프론트엔드를 어떻게 다시 설계해야 하는가?

> 회원 기능이 추가될 때 이 서비스만의 개인화 경험은 무엇이어야 하는가?

를 구체적으로 제안해 주세요.
