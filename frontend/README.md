# What in the World — API 연동

현재 앱은 백엔드에 구현된 조회 API 7개를 사용합니다. 백엔드 코드는 변경하지 않았습니다.

```bash
npm ci
npm run dev      # http://localhost:5174
npm test
npm run build
```

Windows PowerShell 실행 정책으로 npm 실행이 막히면 `npm.cmd`를 사용하세요.
기본 요청 경로는 `/api/v1`이며 개발 서버가 `http://localhost:8080`으로 프록시합니다.
다른 서버를 사용하려면 `.env.example`을 참고해 `.env.local`에 `API_PROXY_TARGET`을 설정합니다.
브라우저가 직접 별도 서버에 접속해야 하는 경우 `VITE_API_BASE_URL`을 설정하고 백엔드 CORS 허용 출처를 맞춥니다.

프로덕션 Docker 이미지의 Nginx는 동일 출처의 `/api` 요청을 백엔드로 프록시합니다.
백엔드 주소는 공용 Docker 네트워크의 `http://backend:8080`입니다.
프론트와 백엔드 컨테이너는 공용 Docker 네트워크에 연결됩니다. 배포 파이프라인의 기본 네트워크는
`witw-app-network`이며 `APP_DOCKER_NETWORK` CI 변수로 바꿀 수 있습니다.
Vite 개발 프록시는 개발 서버에서만 사용됩니다. 브라우저가 외부 API를 직접 호출해야 하는 빌드는
`--build-arg VITE_API_BASE_URL=https://서버주소/api/v1`을 전달할 수 있습니다.

| 화면 | API |
|---|---|
| 글로벌 기사 수 · TOP 5 (1분 갱신) | `GET /global/issues` |
| 글로벌 이슈 정보 · 국가 논조 | `GET /global/issues/{id}` |
| 이슈 미리보기 · 대표 기사 | `GET /issues/{id}/overview?articleLimit=10` |
| 국가 기사 수 · 순위 · 인기 테마 · 양방향 언급 비율 · 대표 기사 | `GET /countries/{code}` |
| 국가 인기 테마 · 시간별 추이 | `GET /countries/{code}/themes/popular?limit=10` |
| 테마 주요 이슈 · 대표 기사 | `GET /themes/{id}/overview?issueLimit=10&articleLimit=10` |
| 분야별 테마 · 테마 검색용 목록 | `GET /themes/by-field` |

국가에서 테마→이슈로 이동하면 **선택한 국가의 논조만** 패널과 지구본에 표시합니다.
테마 상세와 이슈 대표 기사는 국가 필터를 지원하지 않아 전 세계 기준이라고 명시합니다.
논조 평균·최소·최대와 표준편차는 API의 0~100 척도에서 화면의 −1~1 척도로 환산합니다.
국가별 기사 수가 30건 미만이면 평균은 표본 부족으로 숨깁니다. 표준편차는 1건이면 산출 불가,
2~29건이면 참고용, 30건 이상이면 낮음·보통·높음으로 표시합니다. 30일 기준선,
증가율, 매체 수는 제공되지 않아 임의 계산하지 않습니다. 기사 원문 URL과 요약도 현재 응답에 없어
링크 미제공 안내를 표시합니다. 기사 필터는 응답에 포함된 대표 기사에만 적용하며 전체 기사 검색을 뜻하지 않습니다.
국가 언급 비율은 API의 0~1 비율을 백분율로 바꿉니다.

지리 메타데이터는 `src/data/countries.js`에 있습니다. 이전 목업의 합쳐진 지역을 ISO 2자리 국가 코드
(GB, AE, QA, ZA, KE 등)로 분리했습니다. 별도 국가 목록 API가 없어 지도 대상은 이 파일에서 관리하며,
서버에 없는 국가는 조회 오류와 재시도를 표시합니다. 이슈·테마·기사 목업은 실행 경로에서 사용하지 않습니다.

현재 화면 이동은 실제 방문 경로를 따라 뒤로 가며, 기사 화면 내 테마 필터 변경은 같은 경로를 교체합니다.
`src/data/api.js`는 응답 래퍼·오류·타임아웃을 처리하고, `useResource.js`는 로딩·재시도·요청 취소를 처리합니다.
`responseAdapters.js`에서 DTO를 화면 값으로 변환합니다.

검증은 `npm test`의 API 계약·국가 필터·논조 변환·컴포넌트 렌더링 테스트와 빌드로 수행합니다.
실제 백엔드 연결과 브라우저 클릭 검증은 별도로 필요합니다. 수동 화면 확인용 계약 fixture 서버는
`npm run build` 후 `npm run test:browser-server`로 실행하고 `http://127.0.0.1:5175`에 접속합니다.
이 서버는 테스트 전용으로, 실제 API나 운영 빌드에 fixture를 주입하지 않습니다.

## 흰 배경 위의 3D 지구본

화면 전체가 흰 바탕입니다. 그런데 `GlobeThree`는 원래 **검은 우주**를 전제로 만들어진
컴포넌트라, 그대로 흰 바탕에 얹으면 세 군데가 깨집니다. 셋 다 손봤습니다.

| 깨지는 곳 | 왜 | 어떻게 |
|---|---|---|
| 국가 라벨 | 밝은 글자(#E9F0FB)라 흰 여백 위에서 사라짐 | 어두운 글자 + 흰 외곽선으로 뒤집음 |
| 대기 글로우 | 가산 혼합은 흰 바탕에서 곧 흰색 → 안 보임 | 일반 혼합의 옅은 파란 테로 교체 |
| 밤 반구 | 검은 우주에선 배경에 녹았지만 흰 바탕에선 검은 얼룩 | 텍스처를 `emissiveMap`으로 한 번 더 먹여 바닥 밝기를 깔고 방향광을 낮춤 |

여기에 구체가 흰 바탕에 떠 보이지 않도록 아래에 옅은 그림자를 깔고(`.globeSlot::after`),
카메라를 조금 뒤로 빼서 구체가 스테이지 밖으로 잘리지 않게 했습니다.
별 배경(`StarField`)은 흰 바탕에서 보이지 않으므로 쓰지 않습니다.

## 논조 색 — 초록(우호) ↔ 빨강(비판)

논조를 나타내는 곳이 여러 군데라(지구본 채색 · 산포 점 · 트랙 · 뱃지 · 패널 배경 · 범례)
**한 스케일로 통일**했습니다. 한 곳만 초록으로 바꾸고 나머지가 파랑이면 같은 값이
자리마다 다른 색으로 보입니다.

```
비판 ──────── 중립 ──────── 우호
#d94b57      #9ea7b4      #1f9d6b
```

`lib/tone.js`의 `toneRGB()` 하나가 이 스케일을 만들고, 토큰 `--wtw-neg/neu/pos`가
CSS 쪽을 맡습니다.

**표본 부족은 이 스케일 밖의 색(보라 `--wtw-nodata`)** 입니다.
"값이 낮다"가 아니라 "값이 없다"이므로 축 위에 놓으면 안 됩니다.
(코스모스 원본이 빨강–보라–파랑 스케일에서 민트를 고른 것과 같은 이유입니다.)

## 패널 배경 그라데이션 (결정표 4-1 + 코스모스 리더보드)

코스모스에서 이슈 리더보드를 누르면 패널 배경이 그 국가의 논조로 물들던 동작을 가져왔습니다.

| 상황 | 배경 |
|---|---|
| 국가 분석 화면 | 그 나라의 전반 논조 — 우호면 초록, 비판이면 빨강 |
| 그 외 | 없음 (흰색) |

원래는 "이슈 화면 + 국가 필터" 조합도 칠했습니다. 국가 필터를 없앤 뒤로 그 조합이 아예 없습니다.
국가와 이슈를 겹쳐 보는 자리는 이슈 화면의 **국가별 논조** 목록입니다.

표본이 30건에 못 미치면 **색을 칠하지 않습니다.** 못 믿을 값으로 화면 전체를 물들일 수는 없습니다.

색만 바꾸면 "배경이 왜 바뀌었는지" 알 수 없으므로 국가 화면에는 한 줄 설명을 붙였습니다.

> 미국의 전반 논조는 중립입니다. 표본 3,110건 기준이며, 이 값은 패널 배경색으로만 씁니다.
> 개별 이슈에서는 평균 대신 나라별 분포를 봅니다.

## 데이터 모델 (`src/data/model.js`)

```
FIELDS   4개    경제 · 산업·기술 · 외교·안보 · 사회·환경
THEMES  10개    금리 환율 에너지·LNG 반도체공급망 조선·수출
                전쟁·분쟁 통상규제 기후·탄소 원자재·농산물 고용·물가
ISSUES  13개    각 이슈가 국가별 tone: { s: -1~+1, n: 표본 기사 수 }
ARTICLES 28개   국가 + 테마 + 논조 s
COUNTRIES 7개   + m(수집 매체 수)
```

### 손으로 적지 않는 값들 (결정표 1-4)

이슈의 `tone`만 적고, 나머지는 전부 계산합니다.

| 파생값 | 계산 방식 |
|---|---|
| 이슈 총 기사 수 `n` | 국가별 표본의 합 |
| 테마 표본 / 증가율 / 대표 이슈 / 7일 막대 | 소속 이슈에서 |
| 테마의 국가별 보도량 `vol` | 그 나라가 낸 표본 / 테마 전체 표본 |
| 국가간 관심도 | 겹치는 보도 주제 — 아래 참고 |
| 기사 논조 | 그 나라의 테마 논조 + 결정적 해시 편차 |
| 국가 전반 논조 | 표본 충분한 이슈만 가중 평균 (배경색 전용) |

따로 적으면 "테마에는 잡히는데 이슈가 없는 나라" 같은 어긋남이 조용히 생깁니다.
`validateModel()`이 그런 것들을 잡고, 개발 모드에서 콘솔에 남깁니다.
현재 **오류 0 · 경고 12** (경고는 전부 "표본 부족으로 표시됨" 안내입니다).

### 국가간 관심도를 다시 정의한 이유

원본(코스모스)은 국가 인덱스로 만든 숫자였습니다. 그대로 두니
"한국이 가장 관심 있는 나라 = 남아공" 같은 결과가 나왔습니다.

**겹치는 보도 주제**로 바꿨습니다.

```
out(a → b) = Σ_이슈  n_a(이슈) × share_b(이슈)
share_b(이슈) = b가 그 이슈에 쓴 표본 / b의 전체 표본
```

"a가 쓴 양 중, b가 중요하게 보는 주제에 걸린 만큼"입니다.
방향에 따라 값이 달라져서 '보낸 관심'과 '받은 관심'을 나눠 볼 수 있습니다.
한국 기준으로 나가는 관심은 고르게 퍼지고(미국 99, 영국 94, UAE 91),
들어오는 관심은 미국에 크게 쏠립니다(미국 99, 영국 44, 호주 20).

## 어댑터 (`src/data/adapters.js`)

컴포넌트들은 원래 서로 다른 시안에서 왔고 각자 자기 모양의 데이터를 먹습니다.
컴포넌트를 고치는 대신 어댑터를 두었습니다.

| 함수 | 무엇을 무엇으로 |
|---|---|
| `toIssueCard` | 이슈 → `{field, theme, title, count, change, countries, path}` |
| `toThemeCard` | 테마 → `{name, field, count, rise, leadingIssue, bars}` |
| `toArticleCard` | 기사 `s` → `'positive'\|'neutral'\|'negative'` |
| `pinsOfCountry` | 국가 → 지구본 핀 |
| `countryThemeRows` | 국가 기준 급상승 테마 |

`toArticleCard`가 스칼라를 3분류로 낮추는데, 되돌릴 일이 없는 지점이라 손실이 문제되지 않습니다.
**모델이 스칼라를 들고 있어서 가능한 방향**입니다 — 반대였다면 못 했습니다.

| `themes` 테마 전체 | 그대로 | **분야별로 묶은** 테마 목록 (7일 막대) |
| `attention` 관심도 | 그대로 | 방향 전환 + 순위 |
| `theme` 테마 상세 | 그대로 | 요약 3칸 · 소속 이슈 · 대표 기사 |
| `articles` 테마별 기사 | 그대로 | 테마 선택 + 논조 필터 + 피드 |

### 지구본 조작 (결정표 2-C)

- **한 번 클릭** → 지구본에 그 나라만 표시됩니다(국경 강조, 줌 없음). 오른쪽 패널은 그대로입니다.
  같은 나라를 다시 누르면 해제됩니다. 여기서 고른 나라가 헤더 '국가 분석' 탭의 기본값이 됩니다.
- **더블클릭** → 국가 분석으로 전환. 카메라가 그 나라를 향하고 이슈 핀이 펼쳐집니다.
- 두 클릭을 240ms로 구분합니다(`GlobeThree`의 `clickTimer`).

한 번 클릭이 원래는 "목록을 그 나라로 좁히는 필터"였습니다. 그건 없앴습니다 —
**국가에 대한 정보는 국가 분석 화면 하나가 맡습니다.** 이유는 아래 좌표 절에 적었습니다.

## 화면 이동 — 좌표 모델 (`src/navigation.js`)

이 앱의 이동 그래프는 트리가 아닙니다. 이슈로 들어오는 길이 대시보드·테마 상세·기사 목록
셋이고, 이슈 화면에서 다시 국가로 나갈 수도 있습니다.

그래서 화면을 이름(`{name:'issue'}`)으로 들고 다니면 뒤로가기 목적지를 *화면 종류*로
추론하게 되고, "국가 → 테마 → 이슈 → 뒤로 = 대시보드"처럼 두 계단을 건너뛰면서
국가 필터까지 잃습니다. 실제로 그랬습니다.

### 축이 둘이다 — 섞으면 안 된다

```
[분류 축]  전체 ─ 분야 ─ 테마 ─ 이슈     ← 깊이가 있다. 브레드크럼이 그린다.
[국가 축]  전체 │ 특정 국가              ← 깊이가 아니라 on/off. 필터 칩이 맡는다.
```

한때 브레드크럼에 `국가 › 분야 › 테마 › 이슈`를 한 줄로 이어 붙였는데,
그러면 분류 체계가 국가 밑에 매달린 것처럼 읽힙니다. 지금은 국가를 브레드크럼에서 뺐습니다 —
국가는 계층의 한 칸이 아니라 따로 서는 화면(국가 분석)이기 때문입니다.

**화면을 이름 대신 좌표로 표현합니다.**

```js
{
  country: 'us' | null,    // 국가 분석으로 들어감 (더블클릭)
  fieldId: 'econ'| null,   // 분류 1단
  themeId: 'rate'| null,   // 분류 2단
  issueId: 'fed' | null,   // 분류 3단
  aside:   'articles' | 'attention' | 'themes' | null,  // 계층 밖 곁가지
}
```

지금 무슨 화면인지는 좌표에서 파생하고(`levelOf`), 뒤로가기는
**가장 안쪽 칸 하나를 비우는 것**입니다(`backOf`).

| 지금 좌표 | 비울 칸 | 결과 |
|---|---|---|
| `aside` 있음 | `aside` | 곁가지를 열었던 자리로 |
| `issueId` 있음 | `issueId` | 그 이슈의 **테마로** |
| `themeId` 있음 | `themeId` | 그 테마의 **분야로** |
| `fieldId` 있음 | `fieldId` | 국가 개요 또는 대시보드 |
| `country` 있음 | `country` | 대시보드 — 아무것도 남지 않는다 |

핵심은 `toIssue()`·`toTheme()`이 **자기 위 칸을 전부 채운다**는 것입니다.
대시보드에서 이슈로 바로 뛰어도 분야·테마가 채워지므로, 뒤로가기가 계단을 그대로 밟습니다.

```
대시보드 → 이슈 → [뒤로] 금리 테마 → [뒤로] 경제 분야 → [뒤로] 글로벌 동향
```

**축은 하나입니다.** 원래는 국가축(`scope`)이 하나 더 있었습니다. 지구본을 한 번 누르면
목록이 그 나라로 좁혀지고, 그 필터는 계층 이동으로 풀리지 않았습니다. 그걸 없앴습니다.

- 국가 분석에 들어갔다 뒤로 나오면 필터만 남아, 글로벌 동향이 "한국이 다룬 이슈 TOP 5"가 됐습니다.
  세계 전체를 보는 화면에 한 나라 목록이 놓인 셈입니다. 지금은 항상 **실시간 이슈 TOP 5**입니다.
- 같은 목록이 어떤 때는 전체, 어떤 때는 한 나라 기준이라 지금 무엇을 보는지 읽기 어려웠습니다.

지구본을 한 번 누른 나라는 좌표가 아니라 `App`의 지역 상태(`pick`)입니다.
지구본에 표시만 하고, 화면을 옮기면 비워집니다. 목록에서 나라를 눌러 지구본을 돌리는
`spot`도 같은 급입니다 — 둘 다 지구본 상태이지 화면 좌표가 아닙니다.

### 분야는 진짜 칸입니다

결정표 1-3에서 3단(분야 → 테마 → 이슈)을 골랐으니, 분야도 갈 수 있는 화면이어야 합니다.
브레드크럼에 이름만 띄우고 갈 데가 없으면 계층을 선언만 하고 지키지 않는 셈입니다.

- **분야 화면** — 그 분야의 테마 목록 + 그 분야의 이슈 TOP
- **대시보드의 분야 칩** — 위에서부터 밟고 들어갈 문 (`분야로 좁혀 보기`)
- **테마 전체(곁가지)** — 평평한 목록 대신 **분야별로 묶어서** 보여줍니다

### 브레드크럼이 뒤로가기보다 빠릅니다

좌표를 그대로 펼치면 브레드크럼이 됩니다(`crumbsOf`). 각 조각을 누르면 그 칸까지 잘라냅니다.

```
전체 모든 분야 › 분야 경제 › 테마 금리 › 이슈 미 연준 금리 인상 가능성 시사
      ↑클릭        ↑클릭       ↑클릭              지금 여기 (링크 아님, 값은 보임)
```

뒤로가기를 세 번 누르는 대신 한 번에 갑니다.

### 다음: URL 라우팅

이 좌표가 그대로 쿼리스트링입니다(`?c=us&t=rate&i=fed`). 직렬화·파싱 함수 두 개만 붙이면
브라우저 뒤로가기와 공유 링크가 따라옵니다. 결정표 2-1을 뒤집을 때 하면 됩니다.

## 논조를 다루는 규칙

이 앱에서 논조는 `ToneScatter` 한 곳에서만 보여줍니다. 규칙은 셋입니다.

1. **평균을 내지 않는다.** 국가 평균은 그 나라 내부의 분열을 지우고
   "이 나라는 이렇게 생각한다"는 결론을 만듭니다. 결론 대신 분포를 줍니다.
2. **표본이 30건에 못 미치면 값을 적지 않는다.** `표본 부족`이라고만 씁니다.
   숫자를 못 믿을 때는 숫자를 지우는 편이 정직합니다.
3. **편차가 좁으면 경고한다.** 매체가 적은 나라는 편차가 좁게 나오는데,
   그건 "의견이 일치했다"가 아니라 "볼 수 있는 매체가 적다"는 뜻일 수 있습니다.

예외는 국가 화면의 배경색 하나뿐이고, 그 자리에도 "평균이며 배경색 전용"이라고 적어 두었습니다.
